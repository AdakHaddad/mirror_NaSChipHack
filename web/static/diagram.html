Diagram use case

Keaslian identitas dan integritas riwayat tegangan baterai kendaraan listrik, dari provisioning chip sampai pemeriksaan di stasiun penukaran.

Buka PNG Unduh PDF
«include» selalu dijalankan fungsi chip SeBatt stasiun dan server provisioning ancaman / misuse

Aktor dan tanggung jawab

  • Produsen bateraiMendaftarkan ID unik dan kunci K baterai ke server identitas.
  • Pemilik bateraiMemakai baterai, menukarnya di stasiun, dan melihat ringkasan kesehatan.
  • Server identitasMenyimpan kunci dan seq terakhir, lalu memverifikasi keaslian chip serta integritas riwayat.
  • BMS kendaraanMengirim riwayat tegangan bertanda tangan dari jalur data kendaraan.
  • Penyerang / BMS curangMencoba mengubah atau menghapus catatan sebelum stasiun memeriksa.

Yang diuji di dashboard

  • 01Penukaran normalRiwayat lengkap dan tag HMAC cocok, stasiun menampilkan DITERIMA beserta kesehatan baterai.
  • 02Catatan dihapusUrutan seq tidak lengkap, stasiun menolak dengan kode HISTORY_GAP.
  • 03Angka diubahTag HMAC tidak lagi cocok dengan isi catatan, stasiun menolak dengan kode INVALID_HMAC.
  • 04Daya dicabutPenghitung chip kembali ke nol, stasiun mendeteksi ROLLBACK.
  • 05Tiga penolakanChip terkunci dan tidak merespons sampai dibuka untuk demo.
